# 规范 calendar 上的深层 exit 普查

2026-10-17，Claude Opus 5.5。**已通过三方审查并修补（见 §6）。** 本笔记只用已审查的 `work_global_calendar`（`calendar_oracle.py`，未修改）做有限计算，属于 [B] 类证据；不声称任何新的定理、不停机范围扩大或 SQRT-EXIT。

## 1. 做了什么

`projected_epoch(J)` 用 calendar 给出的**规范**交叉数据（真实时间、类型、缺损，而不是自由选取的局部时钟），按 PROOF_M 引理 6.1 的 exit 只依赖 J 这一性质，投影参数为 J 的 fire 的完整 exit。tie、越界、参数不下降都不会被当作闭合（审查已确认）。

两类样本：

1. **随机普查**（`survey.py`）：B=256，40000 个随机 J（均匀、对数均匀、2 的幂附近、3/4·2^b 附近四种分布），J < 2^257。
2. **定向深层构造**（`deep_targets.py`）：对每个深度 m，用 calendar 找真实 fire，使 exit 第一步恰为 j₁=m：
   - b 型首步：取参数恰为 m 的 fire（k 满足 1+v₂(3k+2)=m，在前 8 个提升中搜索），J = 其指针 + 2；
   - a 型首步：取 k 为奇、v₂(3k+1)=m−1 且该时刻确有 fire（在前 64 个提升中搜索），J = 其指针 + 1，此时 j₁ = v₂(3s+2) = m。

   构造方式决定了 J 的位数与 m 只差 −1..2，即 j₁ ≈ log₂J。

**样本偏差。** 深层目标是关于 m 的确定性单参数族（k 取 −2/3 或 −1/3 模 2^{m−1} 的截断），不是随机样本。a(m) 与 b(m+1) 几乎重复（J_b(m+1) ≈ 2·J_a(m)，尾段相同），所以有效样本量约为名义数量的一半；r=3 事件在 m 上准周期出现（周期约 72、144、574、1147）。

- B=4096 中第二步参数 j₂ 的分布（不含 r=1 的 3029 例，共 4968 例）：

- 交叉验证（与 `work_claude_global` 的骨架算法比对）：
  - m=27 的 a 型目标给出 J=50,148,477、exit (J,27,6,1)，类型 aaba；
  - m=28 的 b 型目标给出 J=100,296,964、exit (J,28,6,1)；
  - 骨架算法的第三个 r=3 例 J=351,039,322（exit (J,27,6,1)）不是深层目标，但攻击员用 Calendar(64) 复现了它。所以深层目标并没有穷举所有 r=3 情形。
  - m=28 的 a 型目标 J=501,484,741 超出骨架算法的 4·10^8 范围，无可比对。

## 3. 深层目标的尾段只依赖 m（相位 θ）

在 `projected_epoch` 的相位自动机里：
- a 型首步之后，状态恒为 (j, θ) = (m, 2)，因为根相位 θ=1 经 a 步变为 3−1。
- b 型首步之后，状态恒为 (m, 0)，因为 3s+4 ≡ 0 (mod 2^m)。

此后只用到下标 < m 的交叉数据。所以这些深层目标的尾段（以及 r）是 (类型, m) 的函数；这是因为首步之后的状态固定，并不是关于一般 J 的命题。

据此用 `tails_theta.py` 直接扫描 m ≤ 60000（输出 `tails_theta_60000.txt`，约 1 秒）：

- 全部闭合，无 tie、无不下降；
- 各 r 首次出现：r=1 于 m=2，r=2 于 m=5，r=3 于 m=27（a 型），**r=4 于 m=6131（a 型），尾段 6131 → 14 → 5 → 1**；
- m ≤ 60000 中 r=4 仅出现在 a 型 m = 6131, 6132, 42861, 42862；没有 r ≥ 5。

**规范实例**（`r4_canonical.py` → `r4_m6131.json`）：用 Calendar(6200) 找到 a 型 m=6131 的真实 fire（第 0 个提升，定位约 18 秒），J 为 6130 位整数（SHA-256 记录在 json 中）。其完整 exit 为 **(J, 6131, 14, 5, 1)**，类型 aaaaa，损失 4，closed，即 r=4。这不是 exit 长度的新纪录：已接受的 `work_g2_obstruction` 中有真实 r=6 的 epoch。

**更正。** 此前版本用"j₂ 之后的尾段等于以 j₂ 为根的 exit"估计 r=4 需要约 10^8 个目标，这是错的：尾段依赖到达 j₂ 时的相位 θ（攻击员指出，(j,θ)=(14,1) 即可接出长度 3 的尾段）。正确的有限事实如上。

## 4. 解读（C 类）

- 在这些规范深层目标上，第一步把巨大的 J 降到 j₁ ≈ log₂J，此后由小参数数据决定的短尾段结束。
- r 随 m 增长而缓慢增长（3 于 m=27，4 于 m=6131）。不应从这些数据推断 r 有界，或推断任何具体的增长率。
- 这只是有限的规范证据，对 SQRT-EXIT（PROOF_CLOCK 的剩余目标）没有证明力。它说明在真实可达的源数据上，没有出现 Astra 局部构造中那类高回升。

## 5. 复现

```
cd work_global_calendar_survey
python -B survey.py 256 40000 1          # 约 3 分钟 → survey_B256_s1.json
python -B deep_targets.py 256 250        # 约 1 秒 → deep_B256.json
python -B deep_targets.py 1024 1000      # 约 90 秒 → deep_B1024.json
python -B deep_targets.py 4096 4000      # 约 2.9 小时 → deep_B4096.json / deep_B4096.log
python -B tails_theta.py 60000 20        # 约 1 秒 → tails_theta_60000.txt（重定向）
python -B r4_canonical.py 6131 6200      # 约 20 秒 → r4_m6131.json
```

`deep_targets.py` 现在会把"前 8 个提升中无 b 型 fire"与"超出 calendar 范围"分别计数，不再静默跳过（修补后重跑 B=256，结果不变）。现存的 deep_B1024/4096 输出由修补前的脚本生成，这两种情况在其中都没有发生（每个 m 恰有一条 b 记录）。
